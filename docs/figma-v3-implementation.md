## 디자인 근거와 적용 범위

- [Dark 기준](https://www.figma.com/design/ShVDj8aEDoBYnzWqUNqray/StoryGuard?node-id=50-5)
- [Light 기준](https://www.figma.com/design/ShVDj8aEDoBYnzWqUNqray/StoryGuard?node-id=55-82)
- Figma의 주요 색상·배경 투명도·읽기용 글꼴·원형 노드·근거 비교 배치를 반영했다.
- 기존 작품·원고·분석·검토·관계·떡밥·설정 진입점을 유지한다. Figma에 없는 기존 메뉴도 접근할 수 있어야 한다.
- 앱은 기존 분석 데이터와 관계 배치를 사용한다. 시안의 고정 노드 위치나 인용문을 제품 데이터로 복제하지 않는다.
- 교집합·합집합, 기준 인물 추가, 모델·검색·분석·DB 계약 변경은 포함하지 않았다.
- 실제 렌더러는 SVG이며 Cytoscape는 기존 보조 역할을 유지한다. SVG 색상은 CSS 토큰을 참조하므로 테마 전환으로 그래프 인스턴스나 배치를 다시 생성하지 않는다.
- 드래그를 시작할 때만 포인터를 캡처하도록 수정해 일반 노드·관계 클릭이 뷰포트로 전달되는 문제를 해결했다. 키보드 Enter/Space와 포커스 표시도 제공한다.

## 검증 결과

- 변경 전: 프런트엔드 117개 테스트 통과.
- 변경 후: 프런트엔드 124개 테스트 통과, `npm run build`의 TypeScript·Vite production 빌드 통과.
- Windows의 Chrome headless에서 production 번들을 검사했다. API 응답은 격리된 예시 데이터이며 실제 사용자 원고·AI 계정을 사용하지 않았다.
- 1440×960, 1024×768, 760×720, 390×844에서 가로 넘침 없이 탐색 가능했다. 설치형 앱의 최소 창 크기는 기존 760×720을 유지한다.
- 라이트·다크 전환, OS 변경 추적, 수동 선택 유지, 새로고침 후 복원, 같은 저장소를 쓰는 두 창 사이의 동기화를 확인했다.
- 마우스 노드 선택, 키보드 노드·관계 선택, 확대·이동 이후 테마 전환 시 위치와 선택 보존을 확인했다.
- 관계 인용에서 원고로 이동해 해당 문장이 강조되는 것을 확인했다.
- 브라우저 오류·경고·예상 밖 API 호출·외부 자산 요청은 모두 0건이었다.
- 라이트·다크의 주요 텍스트/배경 조합 18쌍은 계산한 명암비가 모두 4.5:1 이상이었다. 전체 화면의 접근성 인증을 의미하지는 않는다.

## 보안 점검 범위

- 설치한 잠금 파일 기준 npm 의존성 검사: 알려진 취약점 0건. 의존성 버전과 잠금 파일은 변경하지 않았다.
- 변경 파일의 비밀정보 패턴과 실제 차이를 확인했다. 원고·계정·인증 파일·빌드 결과를 커밋 대상에 포함하지 않는다.
- 테마 저장값은 `system`, `light`, `dark`만 허용한다. 별도 키 하나만 저장하며, 저장 실패는 분석 데이터에 영향을 주지 않는다.
- 원문·이름은 기존 React 텍스트 렌더링을 사용한다. HTML 실행 경로, 원격 스크립트, 원격 폰트 로딩을 추가하지 않았다.
- 데스크톱 권한 변경은 기존 main 창의 테마 설정 권한 하나다. 파일·셸·네트워크 권한 범위를 넓히지 않는다.
- 이 점검은 변경 범위와 npm 의존성에 대한 검사다. Python/Rust 의존성 전체 취약점 진단, 침투 테스트, 실제 설치본의 보안 검증을 완료한 것으로 해석하지 않는다.

## 팀에서 확인할 남은 항목

1. 같은 커밋으로 Windows와 Mac 앱을 실행하고 OS/수동 테마, 창 제목 표시, 글꼴 로딩을 확인한다.
2. 실제 원고의 큰 그래프에서 이름 가독성, 트랙패드 이동과 확대, 하단 근거 접근을 확인한다.
3. 기존 모델 준비·AI 연결·분석·판단 저장이 설치본에서도 유지되는지 확인한다. 이번 브라우저 검증은 AI 정확도나 설치 성공을 입증하지 않는다.
